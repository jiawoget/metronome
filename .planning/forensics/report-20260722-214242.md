## Anomalies detected

### A1. Release review was advisory rather than fail-closed — HIGH

**Evidence:** PR #131 had no review; PR #132 had an unresolved Codex finding; repository rules required neither exact-head Codex evidence nor thread resolution.

**Interpretation:** Narrative release policy could be claimed after merge because GitHub did not enforce the same facts.

### A2. Installed OpenGSD instructions drifted from the active Codex schema — HIGH

**Evidence:** Generated adapters required `fork_context` and omission of inline model while the active typed spawn schema accepts explicit model, effort, and `fork_turns`. Agent TOMLs did not provide the missing binding.

**Interpretation:** Resolved Sol routing could silently inherit the global Terra default. Editing generated adapters would create an upgrade-fragile local fork, so the project must bind the live schema explicitly and fail closed where the vendor route is incompatible.

### A3. Mutating-agent authority contradicted repository isolation — HIGH

**Evidence:** `gsd-code-fixer` had a read-only sandbox and an unconditional worktree protocol; project configuration injected no policy into fixer or debugger.

**Interpretation:** The route could only fail late after spending context, or attempt a forbidden workspace topology. It must remain unavailable until both upstream constraints are corrected.

### A4. Completion checked tracked files but omitted external state — HIGH

**Evidence:** stale repositories, open superseded PRs, local/remote branches, Lumen config, global skills, and unresolved GitHub review state remained after the repository cleanup merged.

**Interpretation:** The prior completion boundary ended at the Git diff rather than the effective project system.

### A5. Observability mislabeled receipt delay as execution time — HIGH

**Evidence:** completion events were written when the controller processed results, and the summary named the resulting interval `wall`. The writer and summarizer also resolved `--repo` differently, dropped some event I/O, redacted only by key name, accepted inconsistent model keys, and silently treated unknown budget classes as `standard`.

**Interpretation:** The measurement layer produced precise-looking but semantically false cost data, obscuring rather than explaining the repeated delays.

### A6. Legacy retention had no terminal classification — MEDIUM

**Evidence:** unique and main-reachable branch tips, dirty and clean stale repositories, active open-PR heads, and obsolete global skills were all retained under different ad-hoc mechanisms.

**Interpretation:** Recoverability was used as an indefinite substitute for archive/delete decisions.

## Root cause

The repair was evaluated component-by-component instead of against one end-to-end system boundary. Repository code, installed OpenGSD behavior, GitHub enforcement, global semantic-search storage, and local/remote legacy state each had separate notions of completion. Advisory policy was mistaken for enforcement, upstream-generated instructions were trusted over the live runtime schema, and passive measurement used controller receipt time as agent execution time. The result was another premature completion claim.
